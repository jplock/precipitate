== Background

[NOTE]
====
* Who writes code against the Oxide API (Terraform modules, controllers,
  internal tools), and where do they test it today?
* What does a customer with one rack lose by testing against production?
* What exists already (omicron-dev, the oxide.rs mock server, httpmock) and
  why does none of it cover this?
* RFD 4 proposed a developer playground. What would that have given users?
====

== Goals and non-goals

[NOTE]
====
* Goals: what must a CI pipeline be able to do with patina?
* Non-goals: no VMs, no Crucible, no OPTE networking, no performance
  fidelity. Say why the line is drawn there.
====

== Determinations

[NOTE]
====
Candidates:

* Dropshot API trait, with types from the `oxide` crate.
* No dependency on Omicron's internal crates.
* Long-running operations modeled as reconcilers, not sagas.
* Faults and timing controlled through a separate admin API.
* Conformance is measured against Nexus's published OpenAPI documents.
====

=== Behavioral fidelity

[NOTE]
====
* Errors, status codes, pagination, name-or-id selectors.
* Rules that must be enforced (firewall defaults, disk attach only when
  stopped, limits from the shared profile).
====

=== Fault injection

[NOTE]
====
* Which faults, and why those (map each to an Omicron simulator knob or an
  RFD 704 failure class)?
* How does a test express "fail the third instance create at step X"?
* Indeterminate failures: how are they produced and what do they test?
====

=== Conformance

[NOTE]
====
* How is drift from Nexus detected (OpenAPI diff, CLI scripts, Terraform
  acceptance tests)?
* What happens when Nexus ships a new API version?
====

=== Packaging

[NOTE]
====
* Image, ports, state persistence, startup time target.
====

== Alternatives considered

[NOTE]
====
* Depending on `nexus-external-api` directly.
* Generating a server from the OpenAPI spec instead of a Dropshot trait.
* Steno sagas (and why RFD 704 changed the plan).
* Wrapping omicron-dev in a container.
====

== Open questions

[NOTE]
====
* How should unsupported API versions behave?
* Would Oxide want this upstream, and what would that require?
====

== Security considerations

[NOTE]
====
* patina must never be mistaken for a real endpoint: default bind address,
  obviously fake credentials, clear banners.
* Fixture and state files may contain copied production configuration.
====
